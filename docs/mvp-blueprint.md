# 「跟一口」V0.1 MVP 蓝图

## 1. 本轮目标

把“朋友真实喝水，能否让我顺手跟上”做成可点击、可测试的产品闭环。

本轮验证的不是饮水量管理，而是一次群体行为是否能自然传播：

> 喝一口 → 发出水波 → 朋友跟上 → 发起者得到回应

## 2. 产品口径

- 产品名：跟一口
- 核心表达：你喝的时候，带我一下。
- 核心场景：2–4 位真实认识的人组成一张“小水桌”。
- 核心对象：一轮有时效的“水波”，不是一条催促消息。
- 核心原则：不催、不卷、不监督；不要求填写毫升数。

## 3. MVP 用户流程

### 首次进入

1. 理解产品：朋友真实喝水，而不是系统定时催促。
2. 创建轻量身份：只填写昵称。
3. 创建一张水桌，生成邀请码。
4. 邀请 1–3 位熟人后进入首页。

### 发起水波

1. 用户现实中喝水。
2. 点击“我喝了”。
3. 系统创建一轮水波，并把状态传递给水桌成员。
4. 首页显示水波进度和已跟上的成员。
5. 其他成员跟上后，发起者收到轻反馈。
6. 30 分钟后，水波自然结束并进入记录。

### 跟随水波

1. 好友喝水后，用户在通知或首页感知到一轮水波。
2. 用户现实中喝水。
3. 点击“跟一口”。
4. 头像加入水波，发起者收到“TA 跟上了”。
5. 本轮对用户结束，不继续索要其他操作。

## 4. 首页状态表

| 状态 | 触发条件 | 页面核心内容 | 主操作 |
|---|---|---|---|
| H0 无水桌 | 尚未创建或加入水桌 | 产品解释、邀请入口 | 创建水桌 |
| H1 平静 | 没有进行中的水波 | 水面很安静、最近一次完成状态 | 我喝了 |
| H2 好友发起 | 好友在 30 分钟内喝水，自己未跟随 | 发起者、经过时间、当前参与人数 | 跟一口 |
| H3 我发起 | 自己刚创建水波 | “你的水波正在扩散”、成员进度 | 已喝，不重复记录 |
| H4 我已跟随 | 自己已加入好友水波 | “跟上了”、完整参与进度 | 无强 CTA |
| H5 好友跟随我 | 我的水波获得新响应 | 轻提示“XX 跟上你了” | 查看水波 |
| H6 全员完成 | 水桌所有成员均已跟随 | 轻庆祝、完整圆环 | 完成，返回平静态 |
| H7 网络异常 | 记录暂未同步 | 本地保留记录、非阻断提示 | 自动重试 |

## 5. 事件规则

- 一轮水波默认有效 30 分钟。
- 同一成员在一轮水波中只能参与一次。
- 5 分钟内同一发起者的重复点击合并到当前水波。
- 水桌同时只突出显示一轮最相关的水波，其他事件进入记录，避免通知轰炸。
- 发起者不是“提醒者”；对外文案只描述真实行为。

## 6. 通知语言

### 好友发起

- 阿柚刚喝了一口。
- 阿柚喝水的时候，顺便带了你一下。
- 404 水桌起了一圈新水波。

CTA：跟一口

### 有人跟随

- 林檎跟上你了。
- 你的水波刚刚经过了林檎。
- 已经 3/4 了。

### 全员完成

- 这一圈，大家都跟上了。
- 4/4，水波绕了一圈。

### 禁止使用

- XX 提醒你喝水。
- 你已经很久没有喝水。
- 你落后好友 X 次。
- 今日目标未完成。

## 7. 当前原型范围

已纳入：

- 三步产品引导
- 昵称创建
- 创建水桌与邀请码
- 首页平静态、好友发起态、我发起态、已跟随态
- 水波成员进度
- “我喝了”和“跟一口”核心操作
- 今日记录
- 通知、勿扰和隐私设置的界面表达
- 一组用于用户测试的状态模拟入口

暂不纳入：

- 真实账号和跨设备同步
- 真实邀请码与好友系统
- 系统推送
- 精确饮水量
- 排名、目标和连续打卡
- 桌面 Widget、手表端和硬件联动

## 8. 用户测试重点

1. 用户是否能在 5 秒内理解“我喝了”不是在催别人？
2. 收到水波后，用户是否先现实喝水，再点击“跟一口”？
3. 2/4、3/4 的群体进度是有吸引力，还是会形成压力？
4. “水波”是否比“提醒”更符合轻社交体验？
5. 用户是否愿意为朋友持续点击“我喝了”？
6. 哪一类反馈会带来温和的关系感，而不是监督感？
