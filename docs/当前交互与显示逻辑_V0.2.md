# 跟一口：当前交互与显示逻辑 V0.2

更新日期：2026-09-05  
用途：记录线上版本的真实行为，作为后续调整页面、接口与测试时的统一依据。

## 1. 产品里的三层状态

页面显示由三层状态共同决定：

1. **主分区**：喝水、关系、个人。
2. **主分区内的状态**：喝水首页包含平静、我喝了、他们刚喝了、我已跟随、有人跟随五种状态。
3. **独立流程页**：登录、设置杯子、安装、通知、创建／加入关系、关系详情、账户设置等。独立流程页显示时会覆盖主分区内容。

除登录、开始、首次设置身份和注销完成页外，中间流程页都提供“返回”和“首页”两个出口。底部导航只在三个主分区显示。

## 2. 喝水首页的完整状态机

```text
平静 calm
  ├─ 点“我喝了” ───────────────→ 已发送 sent
  └─ 收到朋友新的喝水信号 ─────→ 待回应 incoming

待回应 incoming
  ├─ 轻点“跟一口” ─────────────→ 已跟随 followed（回应全部当前对象）
  ├─ 长按“跟一口” ─────────────→ 选择对象 selector
  │    ├─ 勾选／取消 ───────────→ 保持在选择对象
  │    ├─ 再点“跟一口” ────────→ 已跟随 followed（只回应勾选对象）
  │    └─ 取消选择 ─────────────→ 待回应 incoming
  ├─ 点“我喝了” ───────────────→ 已发送 sent
  └─ 点“回到首页” ─────────────→ 下一条排队消息；没有则平静 calm

已发送 sent
  ├─ 有人回应这一口 ───────────→ 有人跟随 responded
  ├─ 点“我喝了” ───────────────→ 新一轮已发送 sent
  └─ 点“回到首页” ─────────────→ 下一条排队消息；没有则平静 calm

已跟随 followed / 有人跟随 responded
  ├─ 点“我喝了” ───────────────→ 已发送 sent
  └─ 点“回到首页” ─────────────→ 下一条排队消息；没有则平静 calm
```

### 2.1 平静 `calm`

- 主按钮是“我喝了”。
- 有有效关系且允许发送时，这一口会发送给关系中的朋友；否则只显示为自己的喝水反馈。
- 收到新的朋友信号后进入“他们刚喝了”。

### 2.2 已发送 `sent`

- 点击后立刻在本地切换，以免用户等待网络。
- 一秒内的重复点击会被拦截；动画结束后再次点击代表新一轮喝水。
- 该状态不会因为五秒同步或新消息自动消失；新消息先排队，用户离开结果页后再显示。

### 2.3 待回应 `incoming`

- 横向显示最近 45 分钟内仍未回应的朋友，每人只显示最近一条信号。
- 时间缺失或无效时统一显示“刚刚”，不会显示 `undefined`。
- 轻点“跟一口”回应全部当前可回应对象。
- 长按进入选择模式，初次打开时默认全选；之后的取消勾选会一直保留到确认或取消。
- 选择模式打开期间，五秒同步和新推送可以更新名单，但不能关闭选择面板、切换页面或重新勾选用户；新到达的人默认不勾选。
- 确认时前端只提交仍被勾选且当前仍有效的用户 ID，服务端也只向这些用户写入回应并发送推送。

### 2.4 已跟随 `followed`

- 显示本次实际回应的人，不再引用同步后的全量名单。
- 保持显示，直到用户点“我喝了”或“回到首页”。

### 2.5 有人跟随 `responded`

- 显示实际回应了自己的朋友。
- 不自动退回首页；用户点“回到首页”后把这一批回应标记为已看过。
- 同一批回应不会再次把界面弹回来，新的回应仍会再次进入该状态。

## 3. 两类即时消息的显示顺序

仅当用户位于“喝水”主分区、没有打开独立流程页、也没有正在选择回应对象时，后台同步才允许自动切换首页状态。

“朋友跟了我”和“朋友刚喝了”不再使用固定优先级，而是比较真实发生时间：

| 条件 | 显示结果 |
| --- | --- |
| 两类消息同时存在 | 先显示发生时间更晚的一类 |
| 用户处理当前一类后，另一类仍存在 | 退出按钮显示“查看下一条”，随后立即展示另一类 |
| 正在显示“我喝了”或碰杯结果 | 结果页保持，新消息在后面排队 |
| 正在长按选择回应对象 | 不切页、不改勾选，新消息只更新名单并排队 |
| 两类消息都处理完 | 回到平静 `calm` |

系统推送在页面前台到达时会先拉取云端数据。在其他主分区或普通内页时，新的即时消息会进入喝水分区并按时间选择第一条；在喝水结果页或选择对象期间只排队，不打断正在进行的操作。关系推送只更新关系数据。

## 4. 登录与首次使用

| 当前页面 | 用户操作 | 成功后 | 失败／跳过 |
| --- | --- | --- | --- |
| 登录 | 输入邮箱并发送验证码 | 显示验证码输入 | 显示具体错误，可重试 |
| 验证码 | 输入六位验证码 | 老用户进入首页；新用户进入“开始” | 验证码错误或过期时留在本页 |
| 开始 | 选择创建关系／输入邀请码 | 进入设置身份，并记录后续方向 | — |
| 我的杯子 | 设置名称、杯型与配色 | 云端保存后进入安装 | 保存失败时不离开 |
| 添加到桌面 | 一键安装或继续用浏览器 | 进入通知 | 不支持一键安装时显示真实浏览器步骤 |
| 开启通知 | 允许通知 | 完成设备订阅，进入创建／加入关系 | “以后再说”会关闭三类通知并继续 |

登录会话保存在安全 Cookie 中。安装版和浏览器版是否共用现有登录，最终仍受手机系统与浏览器对 PWA Cookie 的处理方式影响。

## 5. 关系交互

### 5.1 创建关系

1. 输入关系备注。
2. 服务端创建关系和唯一邀请码。
3. 进入“等待加入”，复制按钮只复制纯邀请码。
4. 用户可直接“完成并进入”，关系以待加入卡片保留。
5. 朋友输入邀请码并确认后，双方云端关系更新，创建者收到关系通知。

### 5.2 加入关系

1. 输入邀请码，或打开 `/join/邀请码` 链接。
2. 服务端验证邀请码并返回现有成员预览。
3. 接受后加入关系并进入关系分区；拒绝则返回上一步。
4. 自己输入自己的邀请码时不允许加入。

### 5.3 关系详情

- 修改关系备注：只改变自己看到的备注，并同步到云端。
- “接收这段关系的信号”：控制朋友的“我喝了”是否会发给自己。
- “向这段关系发送信号”：控制自己的“我喝了”是否发给这段关系。
- 退出关系：云端删除自己的成员关系；无人剩余时清理整个关系。
- 创建者尚未等到成员加入时，可以取消邀请。

### 5.4 多人关系添加成员

1. 任一现有成员填写新朋友的临时称呼并发起提案，发起人自动计为同意。
2. 其他现有成员收到关系通知，并在关系页选择“同意”或“不同意”。
3. 任一成员拒绝即结束本次提案，不公开拒绝者是谁。
4. 全员同意后才生成一次性邀请码；原有关系邀请码在关系已有多人后不能重复用于绕过确认。
5. 发起人复制纯邀请码发给新朋友，新朋友接受后加入原关系，该提案随即完成。
6. 邀请被接受前，发起人可以撤回并使邀请码失效。

## 6. 个人与设备设置

| 功能 | 当前真实行为 |
| --- | --- |
| 编辑杯子 | 杯型和配色保存到云端，其他设备登录后可同步 |
| 安装到桌面 | Android Chrome 支持时调用真实系统安装框，否则展示手动步骤 |
| 通知 | 一键申请系统权限、创建推送订阅并保存到云端；每台设备单独设置 |
| 通知分类 | 喝水、回应、关系三类偏好会随该设备的推送订阅保存 |
| 数据说明 | 说明账号、关系与通知数据用途 |
| 退出登录 | 清除本设备会话，并移除本设备推送订阅 |
| 注销账户 | 多次确认后删除云端账户及关联数据，不可恢复 |

## 7. 云端数据与本地状态边界

| 数据 | 保存位置 | 多设备是否一致 |
| --- | --- | --- |
| 账户、杯子、关系、邀请码 | Neon 云数据库 | 是 |
| 喝水事件与回应 | Neon 云数据库 | 是 |
| 关系级接收／发送开关 | Neon 云数据库 | 是 |
| 推送订阅和通知分类 | 云端按设备保存 | 每台设备可不同 |
| 单个成员的备注、接收／发送开关 | Neon 云数据库 | 是 |
| 多人邀请提案、投票和一次性邀请码 | Neon 云数据库 | 是 |
| 当前正在看的首页状态 | 页面内存 | 否 |
| 已看过的回应、已忽略的喝水事件 | 浏览器本地存储 | 否 |
| 安装状态、系统通知权限 | 手机系统／浏览器 | 每台设备不同 |

因此手机和平板可能对同一旧信号显示不同结果：喝水数据一致，但“这台设备是否已经看过／略过”目前是本地记录。

## 8. 已确认的产品规则

1. 未回应的喝水信号有效期是 45 分钟，即一节课的时间。
2. “朋友跟了我”和“朋友刚喝了”按发生时间排序，一次只展示一类，处理后继续下一类。
3. 已看过／已忽略状态保留在当前设备，不做跨设备同步。
4. 关系级开关作用于关系内全部成员；成员级开关只覆盖这一个人。信号必须同时通过关系级和成员级规则。
5. 多人关系添加成员必须经当前所有成员同意，再生成一次性邀请码。

仍需后续观察的一点：同一个人在 45 分钟内连续点击多次时，页面仍按“人”合并为一项，回应后会结束这个人的全部待回应信号。

## 9. 本轮实现结果

- 选择回应对象时只提交实际勾选的人。
- 未回应信号改为 45 分钟有效。
- 两类即时消息按真实时间排队，结果页保持，退出后继续下一条。
- 关系总开关和成员个人开关同时参与云端收发判断。
- 成员私人备注和个人屏蔽保存到云端。
- 多人邀请确认、全员投票、结果通知及一次性邀请码已接入云端。
