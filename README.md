# 跟一口 · 手绘交互 Demo

“朋友喝的时候，顺便带我一下。”

这是根据当前 PRD 和手绘草图制作的移动端可点击 Demo，用来验证“杯子身份、我喝了、跟一口、碰杯反馈”是否容易理解。目前已经包含邮箱验证码账号、云端资料与关系同步，以及浏览器系统推送。

当前视觉试验采用“猫啃什锦黑”，并直接复用草稿中的杯子与底部分区图形。字体授权文件保存在 `assets/fonts/OFL.txt`。

页面实际使用的独立手绘素材表是 `assets/sketches/handdrawn-sprite-v2.png`：包含四种单杯、双杯／三杯碰杯和三个底部图标；页面会去掉浅色底，只保留红色笔触。

## 运行

需要 Node.js 18 或更新版本。

```powershell
npm start
```

然后访问 `http://127.0.0.1:4173`。

第一次打开会进入邮箱登录。输入邮箱后点击“发送验证码”，本地开发版会把六位测试验证码直接显示在输入框下方；配置 `RESEND_API_KEY` 和 `AUTH_FROM_EMAIL` 后，验证码会改为通过邮件送达。完成身份设置后，刷新页面会保持登录与已保存资料。

## 部署到 Vercel

项目在 Vercel 上使用两部分：`dist/` 是静态页面，`api/` 是邮箱登录云函数。浏览器脚本为 `client.js`，不会再被当作 Node.js 服务端入口执行；本地的 `server.mjs` 只用于电脑上预览。

把 GitHub 仓库连接到 Vercel 后无需填写自定义构建设置，仓库中的 `vercel.json` 会执行 `npm run build` 并发布 `dist/`。在 Vercel 项目的 Environment Variables 中添加：

- `AUTH_TOKEN_SECRET`：一段足够长、不可公开的随机字符串
- `RESEND_API_KEY`：Resend API Key
- `AUTH_FROM_EMAIL`：已在 Resend 验证的发件地址
- `DATABASE_URL`：Neon Postgres 连接地址（通过 Vercel Marketplace 连接后自动创建）
- `VAPID_PUBLIC_KEY`：Web Push 公钥，可以公开给浏览器
- `VAPID_PRIVATE_KEY`：与公钥配套的 Web Push 私钥，必须保密
- `VAPID_SUBJECT`：推送服务联系地址，例如 `mailto:code@mail.genyikou.click`

变量名示例保存在 `.env.example`，不要把真实值提交到 GitHub。若暂时只想进行封闭测试，可以在 Vercel 设置 `AUTH_ALLOW_DEV_CODE=true`，页面会直接显示测试验证码；公开测试前应关闭它并配置真实邮件。

连接 Neon 后，云函数会在首次请求时自动创建用户、杯子资料、关系成员、邀请码与喝水事件所需的数据表。生产环境的函数区域设置为新加坡 `sin1`，与数据库保持同一区域。

配置 VAPID 密钥后，用户在“个人 → 通知”开启系统权限，浏览器会保存当前设备的推送订阅。朋友喝水、回应或加入关系时，即使页面没有打开，也会收到系统通知；退出登录和注销账户会移除当前设备订阅。

安卓 Chrome 会通过浏览器提供的系统安装窗口把产品添加到主屏幕；如果浏览器没有开放该窗口，页面会显示对应的菜单安装步骤，不会在未安装时伪造“已完成”。个人页的通知入口可一次完成系统授权、设备订阅和云端保存，网络或系统授权长时间没有响应时会自动恢复按钮并显示原因。

线上验证码和登录状态使用签名令牌，并通过安全的 `HttpOnly` Cookie 保存，不再写入 `.data/auth-store.json`，因此适合 Vercel 的无状态 Function。iOS 17.2 及以上在添加到主屏幕时会复制登录 Cookie，用户不需要因安装桌面版而重新登录；旧版本或已经在本次改动前安装的桌面版仍需登录一次。杯子资料、关系、邀请码和喝水回应保存在 Neon；浏览器本地数据只作为过渡缓存。

## 当前可以体验

- 点击“我喝了”：明显背景出现后转为轻微持续动画
- 他人来信：横向滑动查看杯子身份和相对时间
- 点按“跟一口”：默认回应全部当前信号
- 长按“跟一口”：选择本次要回应的对象，再点同一按钮确认
- 双杯与多杯碰杯：区分回应一人和回应多人
- “喝 / 碰 / 杯”三个底部分区及其选中反馈
- 简化的关系页和个人页，用来验证导航含义
- 邮箱验证码登录、会话保持与退出登录
- 按账号隔离的杯子、关系、备注和通知设置保存
- 好友喝水、回应和加入关系的系统通知

当前 Demo 有意不提供饮水量、次数、排行、连续签到和消息历史。
